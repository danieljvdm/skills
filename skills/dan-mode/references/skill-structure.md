# Writing this stack

Keep each skill's entrypoint focused on its purpose, essential constraints, and decisions that select further guidance. Put task-specific procedures, examples, and tool details in references with concrete read conditions. A short, coherent workflow can stay in one file.

Give shared topics one owner and link to it from related skills. Follow links only to answer the current question, and do not reload guidance already in context. Avoid universal prerequisite chains, mandatory reading of whole reference trees, and files that only forward to another file.

Keep authorization boundaries, critical quality gates, and stopping conditions visible in the relevant entrypoint. Progressive disclosure must not hide rules that govern whether work can proceed or be called complete.

An instruction earns its place by changing a decision or making recurring work more reliable. For recurring mechanical errors, prefer an appropriate type, schema, lint, or shared check; keep concise guidance for the judgment that automation cannot express. Keep review provenance separate from runtime instructions, and record meaningful adaptations when borrowing policy.

Write normal paragraphs and list items without manual line wrapping. Preserve code formatting. Do not require agents to recite principle names, produce process documents, or create tools for every small task.
