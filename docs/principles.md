## Adaptations that matter

- Minimum implementation governs the borrowed principles, including reusable libraries. Model and protect the current contract; do not expand it with speculative validation, authorization, recovery systems, or broad verification machinery. Prefer a lean first version with explicit limits and add focused fixes and regression tests as real cases emerge.
- Boundary discipline does not mean trusting internal state unconditionally. Types do not prove authorization, freshness, or race freedom. Effect services remain appropriate for effectful domain behavior; this is not a pure-functions-only mandate.
- Effect compatibility was checked against Dev Kit's installed Effect `4.0.0-beta.107` guidance and the copied service/error references. The adaptations explicitly use Schema, service requirements and Layer composition, scoped resource/fiber ownership, and Cause-preserving recovery. Test guidance uses Effect's existing test services; local concurrency primitives are not presented as distributed locks. API choices still follow each target repository's installed version.
- A one-consumer library may hide valuable invariants, lifecycle, and recovery. Preserve that boundary; remove pass-through indirection that adds no value. Semantic branding should prevent a plausible mix-up, not become ceremony for every primitive.
- Review assessment applies regardless of the reviewer. Explicit user direction and repository requirements still govern. Omit the upstream tool-specific skip catalog, fixed classification process, and broad ask-by-default policy; use existing evidence and focused checks when a factual question matters.
- Experiments answer a specific unresolved decision. Reuse the real harness where possible, permit a small scratch probe when useful, and promote recurring work into shared tooling. There is no prototype quota, automatic redesign, or mandatory new script, test framework, or permanent artifact.
- Idempotency needs real storage/provider guarantees. A read followed by a write is not automatically atomic; an unknown external outcome must not trigger a blind retry. The additional wording here makes that limitation explicit.
- [Redesign from First Principles](https://github.com/cursor/plugins/blob/99743e9c151c8537cbbf1f98bb38f34ef3368453/pstack/skills/principle-redesign-from-first-principles/SKILL.md), [Outcome-Oriented Execution](https://github.com/cursor/plugins/blob/99743e9c151c8537cbbf1f98bb38f34ef3368453/pstack/skills/principle-outcome-oriented-execution/SKILL.md), and [Migrate Callers](https://github.com/cursor/plugins/blob/99743e9c151c8537cbbf1f98bb38f34ef3368453/pstack/skills/principle-migrate-callers-then-delete-legacy-apis/SKILL.md) inform [evolving designs](../skills/dan-mode/references/evolving-designs.md): choose a coherent destination, deliver within scope, and remove obsolete internal paths after coordinated migration. Preserve actual public and persisted contracts. No general permission for transitional breakage, rewrites, merges, or releases.
- [Sequence Verifiable Units](https://github.com/cursor/plugins/blob/99743e9c151c8537cbbf1f98bb38f34ef3368453/pstack/skills/principle-sequence-verifiable-units/SKILL.md) becomes meaningful verification milestones. Batch related edits and reuse evidence; checking every mechanical edit would contradict your feedback-loop priority.
- [Build the Lever](https://github.com/cursor/plugins/blob/99743e9c151c8537cbbf1f98bb38f34ef3368453/pstack/skills/principle-build-the-lever/SKILL.md) becomes shared tooling for recurring work or a substantial batch whose automation pays for itself. It does not require a new script or committed artifact for every nontrivial task.

## Already covered

The stack covers Laziness Protocol and Subtract Before You Add through the existing [personal simplification workflow](../skills/simplify/SKILL.md), now folded into the stack; Attack the Premise and Fix Root Causes through debugging; Prove It Works and Explain the Number through real-boundary verification and performance evidence; Test Behavior, Not Implementation through Dev Kit's testing references. The new layout gives these ideas clearer homes without adding duplicate principle files. Measurement still needs evidence proportional to the claim, not a fresh profile for every reported number.

## Leave out as defaults

Exhaust the Design Space's mandatory competing prototypes, Guard the Context Window's default delegation, and `how`'s explainer-agent requirement add work regardless of whether the task benefits. Keep those techniques available when useful. Never Block on the Human contributes no new blanket authority: your scope, explicit review requests, and current repository publication policy continue to govern.

Also omit Poteto mode's automatic architecture panels, adversarial reviews, required principle citations in replies, and full autonomy policy. Progressive disclosure means selecting useful guidance for the current decision, not activating the entire upstream workflow.
